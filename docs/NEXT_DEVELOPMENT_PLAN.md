## 維持する方針

- 語彙を変更するのは、既存言語との意味と語形の両方が一致・酷似する場合だけ。距離・部分一致だけでは改名せず、語末だけを理由とする127語の改名も進めない。
- 字形は対応する同じコードの文字と比較する。別の文字との競合は無視する。重要な骨格問題は再編し、非クリティカルなものは軽微調整とする。手書き風の筆流・丸み・周囲の字風を保つ。
- 現時点のWindows／Androidアプリ設計は個人用・完全オフライン・静的辞書。同期・サーバー・アカウント機能を追加しない。
- 自動検証、AI審査、実機での表示確認、人間による使用評価、リリース判断を分けて記録する。

## 1. 文書と現在の成果物を揃える — 最優先

README、総括文書、仕様書の入口を更新する。旧版番号、18子音を16子音とする記載、未検証の「類似ゼロ」「完全完成」、古い語幹例を点検する。辞書・フォント・文書・コーパスは別の版として明記し、現在の台帳と報告書へ誘導する。

開発時の資料取得・辞書生成、配布物への静的バンドル、アプリ実行時の外部I/Oを区別する。「完全オフライン」を、開発中の監査資料の取得まで禁止する意味に読み替えない。既存の封印済み証跡や当時の報告は書き換えない。

完了条件：主要文書の現状説明が辞書v23.3・フォントv2.5・監査の未完了範囲と一致し、旧記録と現在の方針を取り違えない。

## 2. 多言語比較を語義単位で拡張する — 主な監査残点

まず未対応921項目を語義・品詞・専門分野で分類し、最初の50項目を一つの作業単位にする。既存207基本概念に対応しない専門語には、分野に適した出典を追加する。比較先が見つからないものへ無理に近い訳語を割り当てない。

各語義について英・仏・独・西・羅・日の対応、原表記、比較用表記、出典・版・ライセンス、確認理由を残す。辞書全体と比較母集団「約2000語」の数え方・必要範囲も具体化する。単なる語形数の増加で網羅性を認定しない。

距離・部分一致で候補を抽出した後、意味・語形を個別審査する。両条件を満たしたものだけ語族・注記・IPA・辞書4形式をまとめて修正する。資料不足や語義の曖昧さは保留として見える状態にする。

比較器の`scope_complete`は現在常にFalseである。必要な語義・言語・出典・審査の充足から完了を計算する仕組みへ置き換える。Trueを固定代入してWarnを消す実装にはしない。

最初の完了条件：50項目の語義対応と不足理由を記録し、比較数・対象語義・確定候補・除外理由・保留をまとめた新規証跡を保存する。最終完了条件：合意した比較範囲が出典と語義対応で充足し、確定した未修正の類似語が0件になる。資料不足があればWarnを維持する。

## 3. コーパスと使用例を増やす

現在の審査済み5件を基準に、まず合計30例を目標として、格・時制・相・受動・疑問・否定・複文を段階的に追加する。例文ごとに原文・訳・辞書ID・適用規則・語義・項構造を照合する。

現行の限定フレーム検証を言語全体の文法解析器と扱わない。対応しない構文は明示的に未対応とし、必要な仕様を固めてから拡張する。辞書や規則の更新で古い審査が失効する仕組みは保つ。

完了条件：30例の参照・訳・文法の審査記録が揃い、生成された仕様書とWeb標本が一致する。単に検証器を通すために語義や訳を都合よく変えない。

## 4. 字体の使用評価と最小アプリ

フォントはv2.5を基準として、大きな再設計をいったん落ち着かせる。16〜24pxの文章、数字・約物を含む短文、実際の手書きで読みにくさ・書きにくさを集める。直す場合は問題が確認された字形に限定し、入力文字・意味・字幅との関係を記録する。人間の使用評価が未実施なら、その状態を残す。

並行可能なアプリ作業として、Windows向けに静的辞書の検索、IPA・語義・注記の表示、NRS入力と専用フォント表示、審査済み例文の閲覧を持つ最小版を作る。最初は同じNRS文字列をフォントで表示する範囲とし、自由文の自動翻訳や新しい文字コード体系を実装済みと扱わない。

完了条件：ネットワークなしで起動し、1008項目を検索・表示でき、入力・選択・コピーが意図したNRS文字列を保つ。Windowsでの日本語入力とフォント描画を実機で確認する。Androidアプリへの展開は共通部分が動いてから行い、システムIMEは最後に切り分ける。

自動造語、辞書昇格、一般的な双方向構文変換、IME、ピュアKotlinでのTTF生成は後続段階。現在の成果物を利用する最小版に、それらを一度に含めない。
