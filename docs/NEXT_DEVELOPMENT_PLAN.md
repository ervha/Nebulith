### 口語否定と保留語の継続整備

口語否定4形式に意味選択を追加した。進行の否定だけを確認後に生成し、未実施・未完了は未対応の意味として保持する。文ごとに選択を保存し、復元時は再確認する。9保留語には、既存語の参照先・意味の差・残る定義課題を記録し、辞書から関連語へ移動できるようにした。既存語への自動置換や新語根の採用は行っていない。[今回の実装と検証](../audit/maintenance/negative-readings-20261023/report.md)。次は未実施・完了否定の文法根拠の整備、9語の意味再設計案の審査、未対応記録を使う追加表現の選定を進める。

### 1. 翻訳の意味保持・誤成功の防止

最初の実装単位は、逆翻訳の未知引数と必須項／許容格の検証とする。現在の未知述語・主体欠落などの拒否を土台に、項構造が定義済みの述語から段階的に適用する。文型未整備の述語まで正しいと推定しない。既存の登録対訳は照合結果として区別する。

- 日本語→Nebulith、英語→Nebulith、Nebulith→日英の対応表を分け、方向ごとに語義・主語・対象・受け手・場所・時制・否定・相の対応範囲を示す。
- 全入力のどこを解析したか記録し、未知の引数や残った修飾語を省略したまま完成扱いしない。
- 「私があなたに本を譲る／あなたが私に本を譲る」「譲る／譲らなかった」など、一要素だけ変えた期待訳を対にする。
- 複文では否定がどの節にかかるか、節の一部が未対応かを保持する。初版は既に対応する節結合に対象を絞る。

成果物は方向別の対応表、独立して記述した期待訳・拒否例、エンジンと画面の検証記録。出力の全文と意味役割を照合し、未完了時は理由・原文保持・完成訳コピーの無効化を確認する。自作エンジンの往復一致だけを合格条件にしない。

### 2. 既存語彙の文型と用例の整備

第一段階は複合動詞2語と複合形容詞14語の語義整理。動詞は自他・必須項・許容格、形容詞は名詞修飾と叙述・否定・過去を分ける。既存語との意味の境界を確認し、規則が未確定なものは保留理由を記録する。

続いて、残る41動詞を日常的な用途で5〜10語ずつ扱う。「維持する」「仲直りする」「導く」「談笑する」「煎じる」などを優先候補とし、語義の整理後に対象を決める。各単位は次をそろえてから完了とする。

- 出典・語義の範囲と既存語との使い分け。
- 主体・対象等の項構造、日本語活用、Nebulithの生成規則。
- 主体や対象を変えた複数の期待訳、対応する否定・過去、必須項欠落・未知語・別語義の拒否例。
- 辞書詳細で読める用例と対応範囲の更新。未確認の用例を独立審査済みと表示しない。

新語追加は未対応キューから用途を確認して進める。既存語の別語義・表記揺れで対応できるかを先に調べ、同じ意味の語を増やす前に使い分けを整理する。

### 3. 途中入力・会話文の扱いやすさ

「私は」「家で」「少し休みたい」など、名詞句・格句・未完成の述語を状態として示す。未知部分があっても、対応済み部分と未確定部分の位置が分かるようにする。希望などの既存機能は、対応する意味と未対応の意味を確認して拡充する。

複数の名詞語義を選べるUIを追加し、動作選択と同様に元の語句・選択肢・確認状態を保持する。主語省略や前文の話者を使う場合は、補完内容を表示して確認できる形にする。原文を変更した際に古い選択が誤適用されないことを検証する。

完了条件は、途中入力→候補→確認→完成→再編集の状態遷移、複数文ごとの選択、下書き復元後の再確認、意味の取り違えを避ける表示を実用ケースで確認できること。一般自由文への全面対応を一度の完了条件にしない。

### 4. 辞書・語句対応UIの整理

カテゴリ名は元データのラベルと表示用分類の対応表を作り、同一と判断できたものだけ統合する。語形・意味・IDは表示整理に伴って変更しない。検索条件と結果件数を分かりやすくし、条件外の既知語と未収録語を引き続き区別する。

カード・フィルター・ページ送り・詳細画面をキーボードで操作できるようにし、閉じた後のフォーカス位置も確認する。翻訳の対応語句から意味・用例を参照できるようにし、未確定の語句にはその状態を添える。設定保存・お気に入り・履歴は既存実装を検証しながら改善する。

完了条件は、検索→詳細→戻る、語句対応→辞書→戻るの操作で入力・検索条件が意図せず失われず、ライト／ダーク双方と狭い画面で操作できること。

### 5. 実利用確認と公開準備

対応文型を追加する単位で自動検証を行い、公開前に分割版と単一HTML版を確認する。保存・復元・オフラインは既存機能を対象に、今回の変更が影響する経路を検証する。

- IME変換中の入力、確定直後の翻訳、取消・再編集を確認する。
- オフライン起動、下書き復元、Service Worker更新後の新旧データ整合、バックアップ復元を確認する。
- デスクトップとモバイルの表示・タッチ操作を分けて記録する。実機未実施は未実施とする。
- 検証したソースのハッシュ、期待値、実行ログ、失敗と再確認の履歴を保存する。自動検証と人による語義審査を区別する。

語彙・意味・引用に変更があった場合は文学原本への影響を確認し、出典IDを保ってWeb・PDFを更新する。UIだけの変更で本文を再生成しない。公開時はGitHub Pagesの反映まで確認し、ローカル生成の完了と公開完了を分けて記録する。

## 3. 各マイルストーンの詳細仕様と実施計画

### マイルストーン 1: 複文・モダリティ・比較構文の本格対応（表現力の飛躍）

日常会話や物語表現に必要な複雑な複文構造および法（モダリティ）をサポートします。

1. **条件節（Conditional Clauses）**:
   - 構文: `Tor [条件節], [主節].`（もし〜なら、〜である）
   - 対象日本語: 「〜なら」「〜ならば」「〜たら」「〜ば」
   - 例: 「星が輝くなら、私は歩く。」 ➔ `Tor falun el sola, bion el mi.`
2. **モダリティ体系（Modality & Auxiliaries）**:
   - **可能（Potential）**: 「〜できる」「〜することが可能だ」 ➔ 接辞 `-ar` または助動詞
   - **推量・確信度（Evidentiality & Conjecture）**: 「〜だろう」「〜かもしれない」 ➔ 接頭辞 `se-` / 粒子
   - **希望・願望（Desiderative）**: 「〜したい」「〜してほしい」 ➔ 接尾辞 `-ast`
   - **義務・必要（Necessity & Obligation）**: 「〜しなければならない」「〜する必要がある」 ➔ 構文体系化
3. **比較・最上級表現（Comparison & Superlative）**:
   - 比較級: 「AはBより〜だ」 ➔ `... el A ul B [述語]` または起点格 `va`
   - 最上級: 「Aは最も〜だ」 ➔ 最上接頭辞（例: `cel-` [天蓋・最高]）
4. **引用・思考節（Reported Speech & Thought）**:
   - 発話引用: 「彼は『〜』と言った」「彼が〜と言った」 ➔ 引用節マーカー
   - 思考引用: 「私は〜と思う」 ➔ 思考動詞（`cival`, `soras`）との従属節結合

---

### マイルストーン 2: 語彙ネットワークの体系的造語拡張

動詞に続き、文章を豊かに修飾・具体化するための名詞・形容詞・副詞群を体系的に拡張します。

1. **副詞群の整備（修飾語の飛躍）**:
   - 時間・頻度: 「いつも（恒常）」「時々（断続）」「すでに（完了）」「まだ（継続）」「すぐに（即時）」
   - 程度・強調: 「とても・非常に（極大）」「少し（極小）」「全く〜ない（全否定）」
   - 様態: 「ゆっくり（緩慢）」「早く（迅速）」「静かに（沈黙）」「共に（協調）」
2. **基本名詞・事物概念の造語**:
   - 自然・環境: 「雨」「雪」「夜」「朝」「空」「大地」「森」「川」
   - 生活・道具: 「道具」「書物」「服」「門」「光」「影」「音」「歌」
   - 身体・感情: 「心」「瞳」「手」「足」「喜び」「悲しみ」「怒り」「勇気」
3. **フィードバックキュー回収パイプライン**:
   - アプリ内で蓄積された未対応単語（`feedback_queue`）を自動集計・原因分析し、音韻規則（`codaSonorityHierarchy`）に適合した語幹を半自動生成・審査台帳へ登録する仕組み。

### マイルストーン 3: 英語・多言語の双方向生産的翻訳エンジンの確立

日本語 ➔ Nebulith に加え、双方向生産的エンジンへと進化させます。

1. **英語 ➔ Nebulith の生産的文型生成**:

   - 格助詞とアスペクト接尾辞から、自然で滑らかな日本語（敬体・常体）・英語の文を自動生成。
3. **双方向アライメント表示の強化**:
   - 原文と訳文の単語ホバー時に、相互の対応単語がハイライトされるインタラクティブUIの導入。

### マイルストーン 4: Web Studio 学習・字形体験の洗練とオフラインPWA

Nebulithを単なる辞書・翻訳ツールから、人工言語としての「生きた学習・創作プラットフォーム」へと高めます。

1. **単語クリック詳細モーダル（Dictionary Inspector）**:
   - 辞書画面および翻訳結果の単語をクリックすると、詳細パネルがポップアップ：
     - 語幹・品詞・IPA音声記号
     - 語源・造語背景・意味の距離（他語との区別）
     - 全活用形一覧
     - 共起例文・コーパス文
     - Nebulith星石文字グリフ表示
2. **星石文字（Nebulith独自フォント）の専用表示（UIのミニマル化）**:
   - スタジオ全体のフォント切替ボタン（旧 `astralToggleBtn`）はUIの複雑化を防ぐため撤廃。
   - 単語カードのグリフ欄（`.word-glyph`）、詳細モーダル（`.modal-glyph-large`）、コーパスカード（`.corpus-glyph`）などの専用コンポーネント内にて、Nebulith-Regularフォントで直接美しく描画。
3. **PWA（Progressive Web App）化とモバイルUI最適化**:
   - Service Workerによるオフラインキャッシュ（ネット接続なしで完全動作）。
   - スマートフォン・タブレットでのタッチ操作の最適化。
4. **設計方針：手書き文字入力の非採用（明確な除外）**:
   - 手書き文字入力（Handwriting input / Canvas recognition）は操作の煩雑化および精度の観点から**本プロジェクトの要件から完全に除外**。標準的なキーボード入力およびワンタッチ操作、NRS転写入力に集中。
5. **設計方針：AI創発語彙の本番辞書組み込みは人間監査後・Webダッシュボード撤廃**:
   - AI対話等により提案・生成された造語は、自動で本番単語辞書には組み込まず、監査待ち候補台帳（`data/emergent_lexicon_audit.json`）に保留・保持。
   - 人間の本番監査を経て承認されてから初めて正式な単語として辞書に組み込む厳格なガバナンスを徹底。
   - Web Studio 内に設けていた監査ダッシュボードは不要として撤廃し、UIを辞書・相互翻訳・エディタ・コーパスの主要機能に純化。
