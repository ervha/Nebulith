# Nebulith Studio Web

アプリはWeb版に一本化しました。exe・JVM版のビルドや実行環境は不要です。

## 開く

完全オフラインで使う場合は [standalone.html](standalone.html) をブラウザーで開きます。辞書・字体・スクリプトを内包した単一HTMLです。開発・静的サイト配信には [index.html](index.html) と同じフォルダーのファイル一式を使います。

```powershell
python -m http.server 8876
# http://localhost:8876/web/index.html
```

HTTPSまたはlocalhostで開く分割版は、初回読込後にService Workerでオフライン利用できます。配布ファイルの内容からビルドごとにキャッシュ識別子を生成し、更新されたファイルを新しいキャッシュへ保存します。単一HTML版は初回からオフラインで開けます。外部AI・翻訳API・同期サーバーは使いません。

## 機能と保存先

- 1,008語幹と文法語を含む計1,099項目の辞書。日本語・英語・NRS・説明の検索、代名詞などの品詞フィルター、語の詳細表示。
- 日本語→Nebulithの辞書・対応文型による変換。入力途中の語句・格句、解釈候補、完成訳を区別し、主語や動作の補完を確認して確定。
- 登録対訳の日本語・英語・Nebulith表示、専用字体での筆記プレビュー、ダーク／ライト切り替え。
- 例文・対訳コーパス77例の閲覧と検索（公式正本30例・既存の拡張構文23例・新しい学習用例24例）。変換画面には例文呼び出し欄を設けません。
- 翻訳原文・方向・文ごとの解釈、エディター下書き、テーマ・文字サイズ・分割幅、お気に入り・閲覧履歴、未対応キューをブラウザーのlocalStorageへ保存。一括バックアップ・復元に対応。

希望・推量や未知語など、対応できない意味を勝手に補完・省略しません。一般的な自由文翻訳には未対応です。英語入力は否定・主語・目的語を含めて対応文型全体との一致を検証し、未知語や未解析の修飾句が残る場合は未対応として保持します。英語・逆方向の変換は登録対訳と限定されたルールが中心で、日本語入力の解析と同じ対応範囲ではありません。

保存はブラウザー・プロファイル・配信元URLごとです。旧exeのユーザーデータは自動移行しません。file://での保存・クリップボードの動作はブラウザーにより異なり、単一HTMLの置き場所変更でも保存領域が変わる場合があります。保存は単一プロファイルへまとめて行い、旧Web版の個別保存キーも読み込みます。容量不足・保存不可・破損・他タブとの競合を画面に表示し、失敗時に既存保存内容を上書きしません。破損した元データも保持します。

## 生成と検証

PythonとNode.jsを使います。Java・Kotlin・.NETは使いません。

```powershell
.\.venv-audit\Scripts\python.exe tools/build_web_studio.py
.\.venv-audit\Scripts\python.exe tools/verify_web_bundle.py
.\.venv-audit\Scripts\python.exe -m unittest discover -s tests -v
```

生成元は `data/lexicon.json`、`data/grammar_dictionary.json`、`data/translation_extensions.json`、コーパス、`data/corpus_rules.json`、`data/translation_input_rules.json`、`fonts/font_b64.txt` と `web/app.js`・`web/incremental.js`・`web/workspace.js` です。生成物は `data.js`・`index.html`・`standalone.html`・`build-manifest.json`。テンプレートの変更は `tools/build_web_studio.py` で行います。

生産的な活用・項構造・場所語・表記揺れは `data/translation_patterns.json` で管理します。対応範囲の表は `node tools/report_translation_coverage.js` で更新できます。

学習用例は `data/usage_examples.json` です。入力文・期待出力・英訳・解釈条件・注記を管理し、変換エンジンの生成結果と照合します。これらは閲覧用で、登録対訳によるショートカットには追加しません。主語や所有範囲を選ぶ例が、そのまま自動確定されることを防ぎます。日本語・NRS・英語・文型・注記から検索できます。

`tools/verify_web_bundle.py` は正本データとの一致、生成元・生成物のハッシュ、単一HTMLへのスクリプト・字体の内包を検証します。途中入力・検索・記録・文型の挙動はNode.jsでも検証します。日本語IMEやモバイル端末での使い心地は、ブラウザー上の受入確認として別に扱います。

## 文書の位置づけ

アプリの現行構成・対象環境はこの文書を基準にします。`docs/Project Requirements And Design.md` は言語仕様の正本として維持しますが、同文書のKMP・JVM・Android構成案は現在のアプリ構成には適用しません。監査文書中のexe・JVMへの言及は当時の履歴です。

## 未対応記録の回収と語句対応

`web/json_req/` の未対応記録は現在2ファイル・累計9件に対応しています。嫌う nyrcan・殺す kyrdan は追加語彙案として辞書に掲載し、未監査と明示します。正本の1,008語幹へはまだ統合しません。回収記録は `data/feedback_resolutions.json` に原文・出力・元JSONのハッシュを残しています。ブラウザーに保存済みの未対応キューは自動削除しません。

日本語→Nebulithの生成訳には、語句・助詞・修飾・所有・活用の対応を表示します。途中案や解釈候補にも状態を添えて表示し、利用者が補った語は「補完」と明記します。登録済みの複雑な対訳で語別解析ができない箇所は、文単位の対応と表示します。

第2回では未来・過去・物語・想起・展望・予見の追加語彙案と、既存語zyvel（生きる）の文型を追加しました。「あなたが嫌い」は感情の対象を保持して主体の選択を待ち、「私とあなたの物語」は所有範囲を選んで確認します。詳しくは [回収結果](json_req/README.md) を参照してください。

## 例文から一般化した変換

78種類の日本語動詞見出しを、五段・一段・サ変・「来る」の規則から活用させます。現在・過去・否定・丁寧・進行・始動を、辞書の主語・対象・修飾語・所有句と組み合わせられます。78見出しには同じNRSへの別見出しもあり、全体で対応する述語は80です。

授受の「に」はal、移動先はto、居住先はuoとして述語の項構造から選びます。「から」はva。明示した場所語の「で」はuo、具格に対応する述語での道具・材料の「で／を使って」はdeへ対応させます。正本の述語の許容格は上書きしません。

「水は冷たい／冷たかった／冷たくない」のような形容詞叙述にもコピュラを付けます。「美しい」のように辞書候補が複数あれば語義を選択し、確認してから確定します。複数文内では対象の文を選び、補完・語義を個別に確認できます。編集時は同一の原文が一度だけ現れる文の解釈を保持し、変更・重複した文の選択は解除します。再起動後は選択を復元しますが、候補の確定は再確認が必要です。

希望・推量・未知語・未整備の項構造は、単純な現在・未来や反対語に置き換えません。追加の活用・項構造は未監査のアプリ用案として表示します。[対応する見出しと未整備動詞の一覧](../docs/TRANSLATION_COVERAGE.md)で範囲を確認できます。英語・逆方向の一般化は別の課題です。

## JSON取込・状態管理・バックアップ

未対応キューの画面から複数JSONを選ぶと、検証した統合件数を表示します。「検証した記録を統合」で適用します。同じ要求の再取込では回数を二重加算せず、別要求の回数は合算します。言語や解釈が異なる記録は区別し、元要求ID・ファイル情報・取得可能なSHA-256を保持します。原因分類と「未整理・調査中・実装済み・審査待ち・保留」の状態を変更し、JSONへ出力できます。実装済みは独立審査の合格を意味しません。

「保存・バックアップ」から設定・入力・お気に入り・履歴・キューを一括保存できます。復元は形式と内容を検証し、内容確認後の操作で保存データ全体を置き換えます。容量不足や他タブとの競合時は、現画面の入力をバックアップしてから再読込してください。

## 意味の保持と複文

述語・格役割・補完の出所・時制・否定・相・語句対応を共通の意味データへまとめ、NRS出力に使います。「したい／したくない」「かもしれない」「ことができる／できない」「つもりだ」「必要がある」「と思う」は作用範囲を記録しますが、未定義のNRS表現を生成せず保留にします。

「Aなら、B」「Aので、B」「Aけれど、B」「Aとき、B」は、両節が明示した主語を持つ対応文型であれば節を組み合わせて生成します。主語や時制は別の節から引き継ぎません。複数の接続を含む入れ子や未対応の節は完成扱いしません。これらの追加規則と8語の追加語彙はアプリ用の未監査案です。審査状態は `data/language_review_ledger.json` に記録しています。


## 語の詳細表示（2026-10-16改訂）

意味・読み・発音・使い方・基本形を中心に表示します。全件監査済みのバッジ、内部ID、長い由来区分、定型の世界観説明は表示しません。文例は登録コーパスに出典があるものだけを表示し、未収録語の文例を自動で作って埋めません。接辞つき項目を開く際は完全一致の語を優先します。


## 物語用例と原本

各語の「物語の中で」に『ヴァルネス遺聞』の日本語用例、巻名・章・固定の出典番号を表示します。原本リンクはWeb上の `library.html` の該当箇所を開きます。単一HTMLをファイルで開いた場合も引用文と出典は内包し、別ファイルへのリンクは表示しません。物語用例はNRS全文の翻訳ではなく、翻訳エンジンの完全一致対訳にも登録しません。

新しい語を既存辞書へ追加した後は、監査用仮想環境で `python tools/build_publications.py` を実行すると、原本・派生本PDFとWeb引用が更新されます。既存の出典番号と編集した引用は保持します。既存語の意味が変わった場合は生成を止め、物語用例の見直しを求めます。詳細は [原本・追補の案内](../docs/VALNES_SOURCE_EDITION.md) を参照してください。

引用文の話者や引用内の意味が未対応なら「要対応」として記録できます。引用内の主語・動作・語義の選択と確認を反映し、確定前には完成訳のコピーを許可しません。引用符内の句読点では文を分割しません。
