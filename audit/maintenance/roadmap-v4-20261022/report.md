# Roadmap v4 実施・検証記録

実施日：2026-10-22。作業開始時のHEADは `f985971c3c816a7dfcd83603a5dc0f8029b4e66d`。直前の未コミット開発変更を引き継いで実施した。これは実装と限定した受入検証の記録であり、全2,483項目の独立した言語監査合格を付与しない。

## 1. 意味保持・逆翻訳

- 定義済みの項構造に基づき、未知引数・必須格不足・許容外の格・重複格・未解析の修飾語を拒否する。英語からの生成先にも同じ検証を適用する。正本の項構造をテストに合わせて緩めていない。
- 条件 `sen`、理由 `zen` の対応を日本語・英語・逆翻訳でそろえた。英語側で逆転していた旧対応を修正した。
- 英語の形容詞固定表には blue→黒、golden→新しいなどの誤対応があった。辞書の品詞・英語語義から一意に対応する場合だけ採用する。複数候補がある deep などは勝手に選ばない。
- 語根 `zoldar`・`novfar`・`kiranliv` の末尾を接尾辞として誤認する不具合を修正した。辞書の完全一致を優先し、実際に語根から接尾辞を分離した場合だけ活用へ適用する。
- 過去・否定・進行の複数標識を保持し、日本語の形容詞叙述、英語の不規則過去・否定過去・主語に対応する動詞形などを修正した。文末疑問標識 `ka` も認識する。英語入力が従来生成する `ro` は互換用として残る。
- 引用・間接疑問の対応表示は、語を切り落とした見かけの訳を表示せず、節単位の対応と明記する。
- 受け手 `al` は英語で to、定義済み動詞の起点 `va` は「から／from」として比較から分ける。目的格の mi は me、miin は us、riin は them とする。

旧テストの `relen el havsirin al mi` は必須の `ia` がなく、`al` も許容されていなかった。`poran ... ku ...` と `poran ... va ...` も正本ID902の許容格に合わない。これらの旧成功期待値を拒否例へ改め、共格の正例は共格を許容する `cival` に置き換えた。旧失敗は [初回Pythonログ](python-initial.txt) に残す。

## 2. 語義を限定した文型・用例

規則・用例は `data/roadmap_lexical_rules.json`、期待値は `tests/fixtures/roadmap_lexical_goldens.json` に格納した。正本の語形・意味・品詞・ID、および審査台帳の承認状態を変更していない。

従来未整備だった動詞43語に、それぞれ1つの用法の項構造と日本語活用を追加した。日常用語から整備し、自然・内省などの用語へ展開した。日本語動詞見出しは238、対応述語は239となった。未整備動詞一覧は0件になったが、各語の全語義・自他交替・比喩・全構文への対応を意味しない。

複合形容詞14語の処置は次のとおり。

| 対象 | 実装・保留 |
| --- | --- |
| zendarini / bionvyri / zenalin / alinzen / elirzen | 修飾と叙述。叙述の現在・過去・否定・過去否定を検証 |
| biondaron / neranalin / falosvel | 定義に沿った「の」修飾のみ実装。叙述は根拠不足で保留 |
| zenfevas / zencylas / alinfevas / eliralin / elircynel / tykfalos | 品詞は形容詞だが日英の定義が名詞的。語義・品詞の再整理まで生産的変換を保留 |

「肌馴染みの良い」は修飾、「肌馴染みが良い」は叙述として日本語側の形を分けた。保留語の詳細画面には理由を表示する。新しい用例157件は辞書詳細から参照でき、アプリ用案であることを示す。既存の文学原本と出典IDを保存し、PDF本文は変更していない。

## 3. 途中入力・語義選択

「包帯」の2候補 `dariscon` と `valmik` など、名詞が多義の場合は意味を選択して確認できる。選択は文ごとの原文に結び付け、別の解析へ漏らさない。下書きとバックアップで保持し、復元時は確定を解除する。無効な候補IDを渡しても別の語へ確定しない。

前文の明示された主体は補完候補として表示する。選ぶ前に前文の主体へ書き換えない。「あなたは家でくつろぐ。スープを味見する。」の2文目で、利用者が前文の主体「あなた」を選び確認すると `Nerkirel el ti ia darel.` になる。

途中・未対応の入力には、原文中の辞書照合部分と未照合部分を位置付きで保持する。照合部分を連結して原文を再現できることを検証した。この表示は構文解析とは別で、助詞などの未照合部分も残る。未知語の断片が見えたことを翻訳成功とは扱わない。

## 4. 辞書・操作

`data/studio_categories.json` の表示用対応表で、元の97分類を72表示分類へ整理した。複数領域を含む元分類はその範囲を保持し、語の元カテゴリ・意味・IDを維持する。表示分類とバッチを併用できる。

語形と語句対応の辞書リンクをボタンとして操作できる。詳細画面のダイアログ属性、フォーカスの囲い込み、Escapeによる閉鎖、起点ボタンへのフォーカス復帰、フォーカスリングを追加した。全2,483項目の通常検索・ページ送り・お気に入り・履歴は継続する。

## 未確認・保留

- 形容詞6語の品詞・語義、および3語の叙述は上記の理由で保留。規則追加は独立した言語審査の承認を代替しない。
- Androidの `Pixel_10` を開いたが、CLIが `DEVICE_IN_USE`、既存セッション `t3-fb833329c634b255ac051ffc` と報告した。セッションを奪わず、Android上の操作確認は未実施。iOSはmacOS/Xcodeがない環境のため利用不可。
- compositionイベントの試験は合格したが、Microsoft IMEの実入力・候補操作・再変換ではない。物理モバイル端末でも試験していない。
- NLGは登録語義に基づく限定的な生成であり、自然な自由文・比喩・全語義・全従属節の保証ではない。語義の独立審査と実環境の確認は別工程として残す。
- 具体的な用例照合の残点として、既存の renantal の例文 `Renantal el mi ia ti.` は「あなたに適正に譲り商う」という対訳を持つ。アプリ用の「物 ia・受け手 al」の文型案とは格の対応が異なるため、原文・出典を保持したまま、取引の相手と譲渡物を分けた語義審査が必要である。この例文を新文型の正例にはしていない。人称代名詞の ia だけがある曖昧な用例は、逆方向と日本語の生成で自動確定を拒否し、理由を表示する。
- GitHubへのpush・公開は行っていない。本計画の公開準備までを実施し、GitHub Pagesの今回の反映結果は未確認。

再現手順は [Web README](../../../web/README.md) を参照する。今回の試験は正本語彙・文学原本の変更を必要としないため、PDFの再生成は行っていない。

## PR公開時の証拠照合

この報告書の公開前検証では、Windows作業ツリーのCRLFがGit登録時にLFへ正規化されるため、同じテキストでも生バイトのSHA-256が変わることを確認した。`evidence.json` の `sha256` は元の作業ツリーのバイト列を対象とする。追加した `gitBlobSha256` はPRに登録したGit blobのバイト列を対象とし、`git show <対象コミット>:<パス>` の出力で照合できる。元の試験ログ・失敗記録の内容は変更していない。
