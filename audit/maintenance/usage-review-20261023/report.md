## 実装

- 元資料のID・語形・品詞・日英語義・構成語・語源・例文・シナリオIDが検討時の記録と一致しなければWebビルドを停止する。承認済みを名乗る提案や重複IDも拒否する。
- 保留形容詞を逆翻訳の引数・修飾語・並列項に置く抜けを防いだ。通常の形容詞・修飾限定語の修飾は引き続き利用できる。
- 元資料の用例は本文を保存し、「用法確認中」と明記して翻訳入力へのクリック動作を外した。renantalは既に期待訳で検証した譲渡の2用例をアプリ用案として別に表示する。
- 複合語の補足欄から重複する対話全文・内部分類を除き、語源と用法上の注意を読める形にした。原資料とシナリオは削除していない。

## 検証と限界

- Python 81件、Node 25スイート合格（重複あり）。[Pythonログ](python.txt)・[Nodeログ](node.txt)。既存157期待訳等に加え、保留6語×4引数配置×日英の48負例、対応済み修飾の正例、原資料とアプリ用例の表示を確認した。
- 検討元の品詞・日英語義・例文・構成語を試験用コピーで変更すると、再審査要求になる。提案を承認済みに変えることや重複IDも検出する。
- 分割版・単一HTMLの再生成後、生成元と配布物の整合を検証した。文学原本とPDF本文の変更はない。
- T3のデスクトップChromiumで注意書き、保留例のクリック不可、保留修飾語の拒否とコピー無効、正常例でのコピー有効を確認。[DOM確認結果](browser.json)。更新ボタンで新しいService Worker世代を反映してから、簡潔化した注意書きを照合した。
- Android Pixel_10エミュレーター上のChromeで、検索→詳細→閉鎖、日本語の譲渡文→Nebulith→日本語、保留修飾語の拒否理由・完成訳コピー無効をアクセシビリティ情報で確認。[詳細](android-modal.txt)・[正例](android-translation.txt)・[拒否例](android-rejection.txt)。
- AndroidのスクリーンショットではWeb領域が描画されず、見た目の合否は未確定。[画像](android-modal.png)を失敗資料として保持する。アクセシビリティ上の操作・テキスト確認と画像の見た目の確認は別の結果である。
- agent-deviceのfillが既存入力の途中へ挿入するケースがあった。[初回の記録](android-input-fill-failure.txt)を保持し、アプリの消去ボタンで空にしてから入力し直した。再確認では原文が意図した全文と一致し、保留理由で拒否された。
- Androidの入力は自動操作であり、日本語IMEの候補選択を検証したものではない。10.0.2.2のHTTP配信を用いたためAndroidでのPWA／オフラインは今回未検証。物理モバイル、Microsoft IME実入力も未確認。iOSはWindows環境で利用不可。
